NutriCare — Scheda Sicurezza

Versione applicazione: 1.1.0
Data documento: Luglio 2026
Classificazione: Uso Commerciale

1. Descrizione dell'applicazione

NutriCare è un'applicazione desktop Windows per la gestione professionale di pazienti nutrizionali. Gira interamente in locale sul PC dell'utente: non richiede connessione a server cloud proprietari e non trasmette dati sanitari all'esterno.

  • Stack: Spring Boot 3.3.5 + JavaFX 21 (runtime JVM bundled)
  • Database: H2 embedded (file locale, non esposto in rete)
  • Installer: MSI Windows generato con jpackage + WiX Toolset 3.x
  • Percorso dati utente: %USERPROFILE%\.nutricare\

2. Architettura e superficie di attacco

3. Misure di sicurezza adottate

Misura Dettaglio implementativo
Network binding localhost-only server.address=127.0.0.1 in application.properties. Tomcat non risponde a richieste provenienti dalla rete locale (LAN, VPN, ecc.).
H2 console disabilitata spring.h2.console.enabled=false. L'interfaccia web di amministrazione H2 non è mai avviata in produzione.
Cifratura chiavi API (AES-256-GCM) Le API key dei provider AI non sono mai scritte in chiaro. Prima della persistenza vengono cifrate con AES-256-GCM. La chiave di cifratura è nel JAR bundled (acceptable per app desktop single-tenant).
Sistema di licenza RSA-2048 offline La licenza è un file firmato digitalmente (SHA-256withRSA) legato all'ID macchina (hash SHA-256 di MAC address + hostname). La chiave privata non è distribuita nell'applicazione; la verifica usa solo la chiave pubblica embedded.
Isolamento configurazione sviluppo application-dev.properties è esclusa dal JAR di produzione tramite filtro Maven. Nessuna configurazione di sviluppo (es. H2 console abilitata) raggiunge il pacchetto distribuito.
Isolamento dati per utente OS Il database è in %USERPROFILE%\.nutricare\: ogni utente Windows accede solo ai propri dati, in modo trasparente grazie al filesystem NTFS.
JVM bundled (runtime isolato) Il runtime Java è incluso nell'installer (jpackage). Non dipende dalla JVM di sistema; non condivide classpath con altre applicazioni.

4. Rischi residui e raccomandazioni

Rischio Scenario Mitigazione raccomandata
Accesso fisico al PC Un attaccante con accesso fisico alla macchina può leggere il file H2 direttamente Abilitare BitLocker (o EFS) sul volume che contiene %USERPROFILE%. Requisito di policy aziendale, non dell'applicazione.
Prompt AI con dati sensibili L'utente include dati anagrafici nel prompt inviato al modello AI Formare l'utente a usare pseudonimi o identificativi anonimi nel generatore dieta. La funzione genera testo dietetico, non richiede dati identificativi del paziente.
Backup dati Il file H2 non viene copiato automaticamente; un guasto disco causa perdita dati Includere %USERPROFILE%\.nutricare\ nella policy di backup aziendale (Windows Backup, robocopy, Veeam, ecc.).

5. Conformità GDPR — elementi applicativi

  • Residenza dei dati: i dati sanitari restano sul PC locale; nessun trasferimento a server cloud proprietari.
  • Minimizzazione: l'applicazione raccoglie solo i dati inseriti esplicitamente dal nutrizionista (anagrafica, misure, note visite).
  • Diritto alla cancellazione: il nutrizionista può eliminare singoli pazienti dall'interfaccia; una disinstallazione completa rimuove tutti i dati cancellando la cartella %USERPROFILE%\.nutricare\.
  • DPA: un Data Processing Agreement specifico è disponibile su richiesta.
